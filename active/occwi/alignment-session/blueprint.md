# Teresa/Elizabeth Alignment Session - Design Document

## Executive Summary

This document proposes a 90-minute facilitated dialogue between Elizabeth (OCCWI) and Teresa (TFF) to create a shared narrative map defining "the resilience system" across DoD prevention efforts. The session will produce a tangible artifact that clarifies relationships, equities, and strategic direction in language that survives leadership changes.

---

## The Problem

Elizabeth and Teresa are having important strategic conversations about where prevention efforts are collectively heading, but these discussions:
- Happen repeatedly without creating durable reference points
- Involve complex organizational relationships that need clearer definition
- Require alignment between two different organizational perspectives (OCCWI/TFF)
- Need to produce something that outlives leadership transitions

**The convergence challenge:** How do we take two leaders with different organizational contexts and create shared understanding of the resilience system that both can use going forward?

---

## The Briefs Studio Approach

This session uses the **Story Portrait methodology** - a structured facilitation framework designed to surface tacit knowledge and convert complex conversations into actionable narrative artifacts.

### Core Framework: Problem → Path → Purpose

The facilitation uses three sequential movements:

**PROBLEM:** What needs clarifying? What misalignments or gaps exist?
**PATH:** What are the key relationships, structures, and flows that define the system?
**PURPOSE:** What does success look like? What can this artifact enable?

This constraint is the primary value - rather than allowing the conversation to sprawl across all prevention topics, we focus on **the specific question of how to define the resilience system** in a way both organizations can operationalize.

## Session Design

### Duration
90 minutes (can compress to 60 if needed, but 90 is optimal)

### Participants
- Elizabeth (OCCWI)
- Teresa (TFF)
- Megan (optional - strategic insight)
- Mike (facilitator)
- Kate (optional - note capture support)

### Structure

**Opening (5 min)**
- Frame the session purpose
- Establish ground rules (this is thinking out loud, not polished answers)
- Confirm what artifact we're building toward

**Movement 1: PROBLEM (25 min)**
*What needs defining?*

Key questions:
- When you say "resilience system," what are you each picturing?
- Where do current conversations get stuck or vertical?
- What decisions can't be made without clearer definitions?
- What language keeps causing confusion across organizations?
- What will change in 12-18 months if this stays undefined?

*Listening for:* Gaps, friction points, competing frameworks, undefined terms

**Movement 2: PATH (40 min)**
*What are the actual components and relationships?*

Key questions:
- What are the essential elements/nodes in this system?
- How do OCCWI equities and TFF equities relate to each other?
- Where does the IPPW workforce fit in this system?
- What flows between these elements? (Information? Authority? Resources?)
- Who else's equities need to be represented?
- What does "the intervention" actually look like in this frame?

*Listening for:* Organizational relationships, boundaries, leverage points, gaps in current structure

**Movement 3: PURPOSE (15 min)**
*What does this artifact need to enable?*

Key questions:
- Who needs to be able to use this definition?
- What decisions does this clarity unlock?
- How will you know if this is working in 6 months?
- What would make this useful vs. just accurate?

*Listening for:* Success criteria, use cases, stakeholder needs

**Closing (5 min)**
- Reflect back key themes
- Confirm deliverable scope
- Set timeline for draft review

## Deliverable: Narrative Map

### Format
A structured document (8-15 pages) that includes:

1. **Executive Summary**
   - The definition of "resilience system" in 2-3 paragraphs
   - Key insights from the session
   - How this maps to both OCCWI and TFF priorities

2. **System Architecture**
   - Visual map showing nodes, relationships, flows
   - Definitions of key terms and components
   - Organizational boundaries and interfaces
   - Where IPPW/field operations fit

3. **Narrative Framing**
   - The story of how these pieces work together
   - Written in shared language both orgs can use
   - Includes direct quotes/language from the session

4. **Strategic Implications**
   - What this clarity enables
   - Decisions that can now move forward
   - How to communicate this to various stakeholders

5. **Open Questions**
   - What still needs resolution
   - Who else needs to be in conversation
   - Next steps for validation/refinement

### Design Style
- Professional but accessible (not academic)
- Visual elements support comprehension
- Formatted for both briefing and reference use
- Can be presented as slides OR read as document

## Production Methodology

### How the Narrative Map Gets Created

**During Session:**
- Audio recording (with explicit participant permission)
- Live note-taking (Mike + optional Kate support)
- Visual sketching of relationships as they emerge

**Post-Session (Days 1-3):**
- Transcript review and key excerpt identification
- Pattern analysis: recurring themes, tensions, frameworks
- Initial map architecture drafted
- Direct language from participants integrated

**Synthesis (Days 3-5):**
- Visual map created in design tools (Illustrator/Figma)
- Narrative sections written using session language
- Document structured for multiple use cases
- Internal review for accuracy/completeness

**Review Cycle (Days 5-7):**
- Draft delivered to Elizabeth/Teresa
- Feedback session (30-60 min)
- Refinements made
- Final version delivered

### Technical Approach

**Transcription & Analysis:**
The session will be recorded and transcribed. The transcript is processed using a structured template system I've developed specifically for this work. This template guides the synthesis WITHOUT requiring AI processing of government conversation content.

The template includes:
- Framework for identifying problem/path/purpose themes
- Structure for mapping relationships and nodes
- Format for extracting key language and framing
- Design specifications for visual elements

**The actual synthesis work** - identifying patterns, creating the map, writing the narrative - is done by me using standard design tools (Illustrator, Figma, Google Docs). This is the same methodology used for the Prevention Comms system map.

**AI augmentation** (if used) happens only with de-identified structural elements, not conversation content. For example: "Given a system with nodes A, B, C that have X relationship, suggest visual layout options" vs. processing actual Teresa/Elizabeth dialogue.

**When GFE access is available,** the entire workflow can move onto government systems with approved tools. But the core methodology - facilitated conversation → template-guided synthesis → designed artifact - remains the same regardless of tools.

## Why This Approach Works

**The constraint is the value.** By using the Problem→Path→Purpose framework, we prevent the conversation from becoming:
- A general prevention strategy discussion (too broad)
- An organizational authority negotiation (different process)
- A policy development session (not the goal)
- A status update meeting (not generative)

Instead, we focus specifically on: **What is the resilience system, and how do our organizations relate to it?**

**The facilitation creates safety.** As a third party with no organizational stake, I can:
- Ask "dumb" questions that surface assumptions
- Notice when language is being used differently
- Redirect when conversations circle
- Synthesize across different mental models

**The artifact creates durability.** Rather than "great meeting, we should do this again," you have:
- A document to share with others
- Language to use in briefings
- A visual to reference in future discussions
- A baseline for "here's what we've defined" vs. "here's what's still open"
